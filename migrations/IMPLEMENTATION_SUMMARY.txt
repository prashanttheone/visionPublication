================================================================================
🔑 KEY DESIGN DECISIONS
================================================================================

1. PRICE SNAPSHOTS IN ORDER_ITEMS
   ✓ Stores book prices at time of purchase
   ✓ Allows order reconstruction even if book prices change
   ✓ Maintains historical accuracy
   ✓ Required for accounting & dispute resolution

2. SEPARATE ORDER STATUS HISTORY TABLE
   ✓ Creates immutable audit trail
   ✓ Tracks who made what change and when
   ✓ Enables customer service visibility
   ✓ Required for compliance

3. MULTIPLE ADDRESSES PER USER
   ✓ Supports home, office, hostel, other address types
   ✓ Each order uses specific address (snapshot)
   ✓ Users can change default address anytime
   ✓ Flexible for future multi-address requirements

4. OPTIONAL COURSE/SEMESTER IN ORDER_ITEMS
   ✓ Tracks academic context of purchases
   ✓ Enables analytics by program
   ✓ Not required (nullable) for flexibility
   ✓ Supports e-learning use case

5. SEPARATE BOOK_COURSE_MAP TABLE
   ✓ Supports many-to-many relationship
   ✓ Single book can be prescribed for multiple courses
   ✓ Single course can require multiple books
   ✓ Reduces data duplication

🔧 FUTURE UPGRADE EXAMPLES
================================================================================

Example 1: Add Publisher Field to Books
─────────────────────────────────────────
File: 004_books_v2.sql
  ALTER TABLE books ADD COLUMN publisher VARCHAR(255);
  CREATE INDEX idx_books_publisher ON books(publisher);

Example 2: Track Cart Abandonment
──────────────────────────────────
File: 007_shopping_cart_v2.sql
  ALTER TABLE shopping_cart ADD COLUMN abandoned_at TIMESTAMP;
  CREATE INDEX idx_abandoned_carts ON shopping_cart(user_id, abandoned_at);

Example 3: Add Review Moderation
─────────────────────────────────
File: 011_reviews_v2.sql
  ALTER TABLE reviews ADD COLUMN is_approved BOOLEAN DEFAULT FALSE;
  ALTER TABLE reviews ADD COLUMN approved_by VARCHAR(100);
  ALTER TABLE reviews ADD COLUMN approved_at TIMESTAMP;

Example 4: Track Return Requests
─────────────────────────────────
File: 013_returns.sql (new table)
  CREATE TABLE returns (
    id SERIAL PRIMARY KEY,
    order_id INT NOT NULL REFERENCES orders(id),
    order_item_id INT NOT NULL REFERENCES order_items(id),
    reason VARCHAR(500) NOT NULL,
    status ENUM('requested', 'approved', 'rejected', 'refunded'),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
  );
