🗄️ DATABASE SCHEMA - BLOG_POSTS TABLE
================================================================================

TABLE: blog_posts

FIELD DEFINITIONS:
────────────────────────────────────────────────────────────────────────────

id (SERIAL PRIMARY KEY)
  • Unique identifier for each blog post
  • Auto-incremented by database

slug (VARCHAR 255, UNIQUE)
  • URL-friendly identifier
  • Generated from title: "My Blog Post" → "my-blog-post"
  • Used in URLs: /blog/my-blog-post
  • Must be unique (prevents duplicates)

title (VARCHAR 500, NOT NULL)
  • Blog post headline
  • Displayed in listings and detail page

subtitle (VARCHAR 500, NULLABLE)
  • Secondary title or tagline
  • Optional subtitle under main title

excerpt (TEXT)
  • Plain text summary (160 chars max)
  • Displayed in blog listings
  • NO HTML tags (plain text only)

content (TEXT, NOT NULL)
  • Full blog post content
  • ✅ Stores HTML from React Quill editor
  • Can include: <p>, <strong>, <em>, <h1-h6>, <img>, <a>, etc.
  • Sanitized to remove malicious scripts

author_id (UUID, FOREIGN KEY users)
  • References users table
  • Links post to user account
  • NULLABLE (for guest authors)

author_name (VARCHAR 150, NOT NULL)
  • Author display name
  • Used even if author_id is NULL
  • Example: "Dr. Sarah Johnson"

author_role (VARCHAR 100, NULLABLE)
  • Author's title/role
  • Example: "Chief Editor", "Healthcare Specialist"

category (VARCHAR 100)
  • Blog category/section
  • Examples: "Education", "Healthcare", "Research", "News"
  • Used for filtering

tags (JSONB)
  • Array of tags for search/filtering
  • Format: ["nursing", "technology", "education"]
  • Uses GIN index for fast searches

image_url (VARCHAR 500)
  • Featured image URL
  • Displayed as thumbnail in listings
  • Full image on detail page

read_time (INT)
  • Estimated reading time in minutes
  • Calculated from word count (200 words/min)
  • Auto-calculated on create/update

is_published (BOOLEAN, DEFAULT FALSE)
  • Draft vs Published status
  • FALSE = Draft (not visible to public)
  • TRUE = Published (visible)

is_featured (BOOLEAN, DEFAULT FALSE)
  • Featured on homepage flag
  • Useful for highlighting important posts

view_count (INT, DEFAULT 0)
  • Number of times post was viewed
  • Incremented each time retrieved

like_count (INT, DEFAULT 0)
  • Number of likes/reactions
  • Used for engagement metrics

comment_count (INT, DEFAULT 0)
  • Cached count of approved comments
  • Updated when new comment approved

created_by (VARCHAR 100)
  • Admin/editor who created the post
  • Useful for audit trail

updated_by (VARCHAR 100)
  • Last admin/editor who updated
  • Tracks who made changes

published_at (TIMESTAMP NULL)
  • When post was published
  • NULL if still draft
  • Set when is_published = TRUE

created_at (TIMESTAMP)
  • Post creation timestamp
  • Set automatically by database

updated_at (TIMESTAMP)
  • Last update timestamp
  • Updated on every change

💾 HOW TO SAVE QUILL CONTENT
================================================================================

STEP 1: User Edits in React Quill
──────────────────────────────────
The React Quill editor captures rich text:
  • User types content with formatting
  • User adds images, links, code blocks
  • Output is HTML: "<p>Hello <strong>World</strong></p>"

STEP 2: Frontend Sends to Backend
──────────────────────────────────
JavaScript/TypeScript code sends POST request:

  const response = await fetch('/api/blog/create', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      title: 'My Blog Post',
      content: quillEditor.root.innerHTML,  // HTML string
      excerpt: 'Plain text summary',
      category: 'Education',
      tags: ['nursing', 'technology'],
      authorName: 'Dr. Author'
    })
  });

STEP 3: Backend Validates & Sanitizes
──────────────────────────────────────
Node.js/Express endpoint processes:

  1. Validates required fields (title, content, excerpt)
  2. Sanitizes HTML to remove dangerous scripts:
     - Keeps: <p>, <strong>, <em>, <h1-h6>, <img>, <a>, etc.
     - Removes: <script>, event handlers (onclick=), etc.
  3. Calculates read_time from word count
  4. Generates slug from title
  5. Creates excerpt if not provided

STEP 4: Save to Database
────────────────────────
INSERT INTO blog_posts (
  slug, title, excerpt, content, category, tags,
  author_name, read_time, is_published, created_at
) VALUES (
  'my-blog-post',
  'My Blog Post',
  'Plain text summary',
  '<p>Hello <strong>World</strong></p>',  // ✅ HTML stored as-is
  'Education',
  '["nursing", "technology"]',
  'Dr. Author',
  5,
  FALSE,
  NOW()
);

STEP 5: Retrieve from Database
───────────────────────────────
GET /api/blog/my-blog-post

Returns:
  {
    id: 1,
    slug: 'my-blog-post',
    title: 'My Blog Post',
    content: '<p>Hello <strong>World</strong></p>',
    author_name: 'Dr. Author',
    category: 'Education',
    view_count: 42
  }

STEP 6: Display in React
────────────────────────
Use dangerouslySetInnerHTML to render HTML:

  <div dangerouslySetInnerHTML={{ __html: post.content }} />

Browser renders:
  Hello World (with "World" in bold)

================================================================================
🔒 SECURITY CONSIDERATIONS
================================================================================

HTML Sanitization:
✅ ALWAYS sanitize HTML on backend
✅ Use DOMPurify or similar library
✅ Whitelist allowed HTML tags
✅ Remove event handlers (onclick, onerror, etc.)
✅ Remove script tags

Content Validation:
✅ Check title/content are not empty
✅ Limit maximum content length
✅ Validate image URLs if included
✅ Check file uploads for malware

Access Control:
✅ Only authenticated admins can create posts
✅ Verify user permissions before saving
✅ Use database constraints

Example Sanitization (Node.js):
────────────────────────────────
const DOMPurify = require('isomorphic-dompurify');

const cleanContent = DOMPurify.sanitize(userContent, {
  ALLOWED_TAGS: [
    'p', 'strong', 'em', 'h1', 'h2', 'h3',
    'ul', 'ol', 'li', 'blockquote', 'img', 'a', 'code', 'pre'
  ],
  ALLOWED_ATTR: ['href', 'src', 'alt', 'style']
});

📊 TABLE RELATIONSHIPS
================================================================================

blog_posts (main table)
    ├─ Foreign Key: author_id → users(id)
    │  (Links blog posts to user who created them)
    │
    ├─ Referenced by: blog_comments
    │  (Readers can comment on posts)
    │
    └─ Referenced by: blog_ratings
       (Readers can rate posts)

blog_comments
    ├─ Foreign Key: blog_post_id → blog_posts(id)
    ├─ Foreign Key: user_id → users(id)
    ├─ Foreign Key: parent_comment_id → blog_comments(id)
    │  (Supports nested/threaded replies)

blog_ratings
    ├─ Foreign Key: blog_post_id → blog_posts(id)
    ├─ Foreign Key: user_id → users(id)
    └─ UNIQUE(blog_post_id, user_id)
       (One rating per user per post)

📈 EXAMPLE QUERIES
================================================================================

Get Published Posts with Comment Count:
────────────────────────────────────────
SELECT 
  bp.id, bp.slug, bp.title, bp.author_name,
  COUNT(bc.id) as comment_count
FROM blog_posts bp
LEFT JOIN blog_comments bc ON bp.id = bc.blog_post_id
WHERE bp.is_published = TRUE
GROUP BY bp.id
ORDER BY bp.published_at DESC;

Search Posts by Tag:
────────────────────
SELECT * FROM blog_posts
WHERE is_published = TRUE AND tags @> '["nursing"]'::jsonb
ORDER BY published_at DESC;

Get Trending Posts (Most Views):
─────────────────────────────────
SELECT * FROM blog_posts
WHERE is_published = TRUE
ORDER BY view_count DESC
LIMIT 10;

Get Average Rating for Post:
─────────────────────────────
SELECT 
  AVG(rating) as avg_rating,
  COUNT(*) as total_ratings
FROM blog_ratings
WHERE blog_post_id = 1;

Get Recent Comments on Post:
─────────────────────────────
SELECT * FROM blog_comments
WHERE blog_post_id = 1 AND is_approved = TRUE
ORDER BY created_at DESC;

💡 KEY CONCEPTS
================================================================================

Rich Text Editor:
  • React Quill captures formatted content
  • Output is HTML (not plain text)
  • Supports images, links, code blocks, etc.
  • User-friendly WYSIWYG interface

HTML Storage:
  • HTML is stored in database as-is
  • Allows preservation of all formatting
  • Must be sanitized before storage
  • Can be rendered directly in browser

Content Rendering:
  • dangerouslySetInnerHTML displays HTML
  • Alternative: Use HTML parser library
  • Sanitize content before rendering
  • Validate HTML is safe

Database Performance:
  • Use indexes on frequently queried fields (slug, category)
  • JSONB tags allow efficient filtering
  • GIN index optimizes tag searches
  • View count tracking for analytics
